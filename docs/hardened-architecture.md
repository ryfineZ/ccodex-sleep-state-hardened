# 兼容网关的设计与边界

## 一次请求

1. 检查回环来源、Host、端点、请求头和并发上限。
2. 从客户端当前请求头计算凭据/工作区作用域哈希，不读取账号文件。
3. 检查该作用域是否处于上游认证拒绝或限流等待。
4. 已有 state 使用原绑定出口；无绑定时选择可用出口。原 state 逐字保留，不把别的 state 换进去。
5. 获取出口健康租约，冻结本次 Cookie 快照，正式请求只派发一次。
6. 接收 Set-Cookie，经过白名单与作用域检查后保存到内存；不将其直接暴露给本地客户端。
7. 流式转发正文，在有界事件缓冲内观察完成、失败、限流和 state metadata。
8. 无论 EOF、读错误、关闭还是 ReverseProxy 中止，完成一次记账。客户端取消不归因于代理。

## 四种状态分别管理

- **代理健康**：healthy / suspect / open / half_open。只根据可归因的传输结果变化。
- **账号停止规则**：认证拒绝与限流独立于代理；换出口不清除它。
- **Cookie**：仅内存、按源站及作用域隔离；每个请求读取不可变快照，按请求顺序防止旧响应覆盖新版本。
- **turn 路由记录**：只保留 state 哈希与出口编号，不自行解释 state 的密文或时间字段。

不同请求的网络完成顺序可能与开始顺序相反。熔断器使用 epoch 和请求序号防止迟到的成功把新的失败清零。
熔断冷却后，通过下一次适合使用该出口的真实请求进行半开试探，最多同时一个；没有后台付费探测。
被锁定的 turn 遇到熔断只返回本地 503，不能悄悄改走其他出口。

## 错误归因

| 现象 | 处理 |
| --- | --- |
| 连接/代理握手失败、上游读错误、上游流读取空闲超时 | 增加代理失败计数，达到阈值熔断。 |
| 客户端取消或提前结束读取 | 中性结果，不处罚代理。 |
| 完整 HTTP 401/403 | 该凭据作用域停止，等待客户端解决认证。 |
| 完整 HTTP 429 / 已识别的 SSE 限流码 | 保存暂停截止时间，尊重 Retry-After，至少暂停 30 秒。 |
| 完整 HTTP 5xx / 明确 SSE 应用失败 | 保留上游错误，不单次归咎代理，不自动重放。 |
| 干净 EOF 但没有完整终止事件 | 标为不完整，不计为已完成生成。 |
| 事件超过观测上限或响应压缩无法直接观察 | 正文继续转发，统计为观测受限，不伪称已验证成功。 |
| 上游重定向 | 不跟随、不向客户端下发跳转地址；本次返回本地 502。 |

收到上游拒绝前已获准、已在途的请求不能保证撤销，可能已经产生费用。网关只约束之后的准入。
所有停止记录保存在当前进程 RAM，重启不表示上游权限或额度已经恢复。

## Cookie 安全

只允许 `__cflb` 与 `__oailb`，同名不同合法路径仍遵循标准 CookieJar 规则。
保留 Secure、Expires、Max-Age、Path 和删除语义；禁止扩展到兄弟域。
作用域包括 Authorization 的哈希、ChatGPT-Account-Id、OpenAI-Organization、OpenAI-Project、源站和出口。
不接受浏览器传入的任意 Cookie，不把 Cookie 发送到用户未配置的外部上游。
无过期字段的 Cookie 使用可配置的本地保留上限；这不构成对服务端寿命的推定。
最多保留 128 个 Cookie 作用域，迟到的响应不能复活已被淘汰的作用域。

## 资源边界

默认最多 32 个并发、64 MiB 请求体，SSE 每事件观察缓冲最多 256 KiB。
state 头最多 4096 字节，仅检查是否为安全的 HTTP 头值，不套用长度判断模型。
账号守卫最多 128 个，turn 路由对应最多 4096 项。本地无可用容量时拒绝，不偷偷扩大缓存。
路由列表最多 256 条，健康记录不会从外部请求增加任意节点。

## 与旧入口的区别

此实现采用独立命令和独立配置，不加载原项目采集器，不接入旧管理面板，也没有假称旧代理池问题已全部修复。
原始源码和原有测试保留，便于后续审查差异。应运行 `ccodex-reliable-proxy` 而不是旧入口来验证这里的新功能。

## 协议依据

Codex 官方源码将 turn-state 作为 turn 级状态；同一 turn 内保留，不应以网关长期票池代替客户端所有权。
当前实现同时观察 HTTP 头以及 `response.metadata` 的 `headers` 中返回的状态，不修改正文。
