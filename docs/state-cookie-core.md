# State + Cookie 核心模式（0.5.0）

核心链路已接入根目录的一键程序，不需要另开采集器或 reliable-proxy：

`客户端生成请求 → 受控采集 → 缓存 state 与路由 Cookie → 经采集出口注入一次正式请求 → 观察响应并更新 Cookie`

## 操作

双击根目录 `start.command` / `start.cmd`，点击「一键接入 Codex」。在首页「核心功能」中勾选「开启采集与注入」，点击「应用核心设置」并确认采集可能消耗额度，然后重启 Codex、新建会话正常使用。

第一次请求提供凭据后才开始采集。只想抓包时不启用核心开关；模型改写是另一个默认关闭的开关。退出使用「恢复并退出」。

核心设置只保存在当前进程内。默认不发送额外请求，必须明确开启。配置文件支持 `state_core` 对象；一键接入重新选择连接时会关闭核心，需在页面确认开启，防止将旧设置静默用于新的上游。

## 采集与注入

只为 `POST /backend-api/codex/responses` 的普通生成请求采集。模型、凭据、工作区和上游分别隔离。采集请求使用固定短提示词，不携带用户对话、previous_response_id、客户端 state 或 Cookie。认证凭据只借用客户端当前请求，保存在内存，不导入或刷新登录文件。

必须读到完整、无失败的 SSE 回复；从响应头或 `response.metadata` 提取 state，同时接收 Cookie。通过本地封装和账号形状规则，并且存在可用的 `__cflb` / `__oailb` 路由 Cookie，才能发布候选。缺少 Cookie、异常时间、错误形状、截断或流内失败不能算采集成功。个人/Team 的形状规则只是经验规则，不是签名或模型质量验证。

正式请求保持原正文（除非另行开启模型改写），注入候选 state 和已采集的路由 Cookie，保留其他客户端 Cookie，使用该候选采集时的出口。每次请求固定自己的候选和 Cookie 快照，不自动重放正式生成。响应的 `Set-Cookie` 更新内存 Cookie；旧响应不能覆盖更新版本。压缩/compact 路径不额外采集或强行注入。

## 刷新与失败恢复

默认本地新鲜度上限 120 秒，取 state 时间和采集时间上限的较早者。服务端 Cookie 的过期/删除语义独立生效；Cookie 缺失、组合过期、连续两次返回异常形状或关联出口熔断，都会影响后续请求准入。成功使用不延长 state 的本地期限。

刷新按请求驱动：没有可用组合或剩余新鲜度不超过 20 秒时受控补充。首页可手动补充备用，失败不清除已有可用组合。没有后台 hunter，没有空闲时无限采集，也没有自适应寿命预测器。缺少可用组合时明确返回本地错误，不静默无票转发。

默认两轮采集至少间隔 30 秒、单次超时 20 秒、每轮最多 2 次、每个凭据作用域每小时最多 30 次；所有模型共享该凭据预算与暂停状态。HTTP 401/403/429 和已识别的 SSE 限流会阻止后续请求。手动刷新、切模型、切模式、修改采集配置都不清除账号暂停或采集预算。

网络故障独立触发熔断：连续两次可归因的连接/读取失败后冷却，30 秒起指数退避至 5 分钟；冷却到期只放行一个半开尝试。客户端取消、state 形状不匹配、完整的上游应用错误不直接处罚代理网络健康。活跃 state 的出口失败后会进入受控补充流程，不再卡在「state 可用但出口不可用」。

「采集与代理设置」中可填最多 32 个明确的 HTTP/HTTPS/SOCKS 出口。没有自定义池时，使用一键接入已经选择的连接；填写池后只使用池中出口，不回退直连。不在此入口导入整个旧订阅控制面。

## 页面与数据

首页显示采集中、组合可用、等待组合、账号暂停、票龄、本地新鲜度剩余、Cookie 数量、主备状态、采集冷却、小时预算、出口健康和最近 50 次采集诊断。

正常请求记录的 `state_core` 字段是本次注入快照，包含指纹、版本、数量及出口，不包含完整秘密值。`injected` 表示已准备注入头部，计数是发送尝试，不证明上游执行成功。采集诊断只驻留内存，不存完整提示、票或 Cookie。显式 full 抓包仍可能保存正式请求中的完整敏感头部，遵守原来的确认与私有存储规则。

## 接口与实现

管理 API 仍需当前本地令牌并校验来源。`POST /__recorder/api/state-core/configure` 接受核心策略，开启时需 `confirm_cost: true`；返回 `persisted: false`。`POST /__recorder/api/state-core/refresh` 接受已有会话的 `id` 与 `confirm_cost: true`，不会导入新账号或绕过限制。

实现位于 `internal/requestrecorder/state_core.go`、`state_core_stream.go`、`state_core_api.go`，复用 `internal/cookiebundle` 和 `internal/routehealth`。独立记录、模型检测、可选模型改写和一键恢复仍然可用，未恢复模型别名。

## 协议与验收边界

官方 Codex 客户端将 `x-codex-turn-state` 定义为同一 turn 内的粘性路由状态。将短采集得到的 state 在后续 turn 使用超出了这个客户端约定，因此核心复用被明确标为实验功能，不能宣称获得上游有效期或实际模型身份保证。

依据：`https://github.com/openai/codex/blob/main/codex-rs/core/src/client.rs` 的 `ModelClientSession` 注释。默认只允许官方 ChatGPT 源站或用户指定的字面量回环 HTTP 测试/受信本地端点；API `/v1` 和其他生成协议不借此自动采集。

本轮只使用本地模拟上游、合成凭据和隔离浏览器验证。真实账号、真实代理线路及服务端复用窗口仍需实际环境验收。合成测试通过不等于已验证真实模型质量。
